# Явная иконка и значок окна сессии из claude-wt CLI — дизайн

Решения Стаса 23.11. Продолжение `2026-11-23-project-badges-design.md`.

## Зачем

Однотипных сессий много, и отличать их нужно на панели задач. Правила
`badges` угадывают тип по заголовку, но агент свою задачу знает точнее любого
регэкспа. Поэтому агент (или head для своего ребёнка) должен уметь **явно**
поставить окну своей сессии иконку и значок — и явное важнее всего
автоматического.

## Цели

- `claude-wt window icon <session> <имя>` — главная иконка окна (WM_SETICON).
- `claude-wt window badge <session> <имя>` — значок в углу кнопки на панели
  задач (overlay, тот же слот, что у head и `badges`).
- `--clear` у обеих — снять заданное, вернуть автоматическое.
- `claude-wt window icons` — какие имена можно ставить (список папки иконок
  машины окна).
- Выбор — только из папки иконок машины окна; у Стаса `C:\images\ico`.
- Два скилла для агентов: `set-icon`, `set-badge`.

## Не цели

- Произвольные пути к файлам из CLI — только имена из папки.
- Значок в пикере, заголовке окна, Alt+Tab (как и у `badges`).
- Загрузка новых иконок через CLI: файлы в папку кладёт человек.
- Правка конфига: заданное агентом в `windows11-manager.config.yaml` не пишется.

## Анти-цели

- Агент меняет иконку чужой сессии — CLI действует только на свою сессию и её
  потомков (правило всех команд `claude-wt`).
- Заданное молча не применилось: команда отвечает, что поставлено, или
  отказывает с причиной (нет такого имени, нет окна, нет менеджера).

## Приоритет (решение Стаса — вариант A)

Главная иконка: **явная** > значок head в `headMode: icon` > иконка проекта /
профиля.
Значок на кнопке: **явный** > значок head (`badge`) > первое правило `badges`.

Явный значок вытесняет значок head, пока его не снимут: правило одно для всех
сессий. Цена принята: head с явным значком на панели задач как head не узнать.

## Подход (выбран Стасом)

Хранить заданное **отдельным файлом у службы** (`node src/index.js mqtt`):
http-слушатель команд и служба иконок (`src/mqtt/window-icons.js`) — один
процесс. Запрос пишет файл и сразу переставляет значки, не дожидаясь чужого
тика.

Отвергнуты:
- слот сессии в состоянии демона (как `unreadAt`) — демон другой процесс,
  понадобилась бы передача через файл просьб и ожидание его тика ради поля,
  которое демону не нужно;
- живой конфиг (как `projects[].icon`) — его правят руками, а агенты насорили
  бы туда записей на каждую сессию.

## Как устроено

**Конфиг менеджера.** Новый ключ `claudeWt.windowIcons.dir` — папка иконок
этой машины (у Стаса `C:\images\ico`). Нет ключа — команды отказывают
(«icons dir not configured»), автоматика работает как раньше.

**Имена.** Имя — имя файла без расширения, сравнение без учёта регистра. В
список и к установке годятся только `.ico` — значку на кнопке нужен малый
кадр, а `.png` его не даёт (*решение исполнителя дизайна: проще одно правило
на обе команды*). Имя — только из списка файлов папки: путь, `..`, разделители
— отказ. Поиск плоский, без подкаталогов (у Стаса папка плоская, проверено
23.11). Файл ищется в момент команды; пропавший позже файл — служба
предупреждает, как сейчас о любой не вставшей иконке.

**Хранилище.** JSON-файл службы на машине окна, ключ — `sessionId`:
`{ icon?: <абсолютный путь>, badge?: <абсолютный путь>, at: <мс> }`, где `at`
— когда запись последний раз была нужна: задана командой или её окно было на
экране. Освежается службой, но пишется на диск не чаще раза в сутки —
открытое месяц окно не теряет заданного, а диск не трогается каждый тик
(*решение исполнителя дизайна*). Место — каталог данных менеджера (рядом с журналом трея),
*решение исполнителя дизайна*. Запись атомарная (`writeFileAtomic`). Записи,
не нужные дольше 30 дней, удаляются при записи файла (*решение
исполнителя дизайна; срок — константа*). Привязка к `sessionId` значит:
заданное переживает перезапуск трея и `--resume` (id тот же), не переживает
новую сессию.

**Служба иконок.** `iconFor` получает явное заданное сессии и ставит его поверх
автоматики по приоритету выше. Изменение файла попадает в отпечаток тика, и
значок переставляется на ближайшем тике; запрос дополнительно зовёт тик сразу.
Явная иконка уходит демону и в файл трекера как обычная иконка окна — пикер
покажет её в строке сам.

**Когда поставить нельзя — сохранить и сказать почему** (*решение исполнителя
дизайна*). Команда всегда сохраняет заданное (`ok: true`, код 0) и отвечает
`applied: false` с полем `reason`: `no window` (окна сессии на машине нет),
`icons disabled` (`windowIcons.enabled: false` или `claudeWt.enabled: false` —
выключенные иконки выключают и явные), `no overlay support` (у `badge`, аддон
без `SetOverlayIcon`), `no icon service` (аддон без `SetWindowIcon`).
Заданное встанет само, когда причина уйдёт. Отказ (`ok: false`, код 1) — только
когда сохранять нечего: нет `windowIcons.dir`, неизвестное имя. Поэтому
маршруты пишут файл сами, а службу иконок лишь подталкивают, если она есть, —
порядок сборки роутера и службы в `service.js` от этого не зависит.

**Маршруты менеджера** (http, как у `session-unread`; MQTT-двойник не нужен —
CLI ходит только по http):
- `POST /claude-wt/window-icon` `{ id, icon: <имя> | null }`
- `POST /claude-wt/window-badge` `{ id, badge: <имя> | null }`
- `POST /claude-wt/window-icons` `{}` → `{ ok, dir, names: [...] }`

Ответ установки — `{ ok, id, icon|badge: <путь|null>, applied: bool, reason? }`
(причины — выше). Неизвестное имя — `ok: false`, `reason` со
списком ближайших имён не нужен, хватит «unknown icon <имя>; see claude-wt
window icons».

**CLI** (`ccfzf/cli`, новые `window-icon.mjs`, `window-badge.mjs`,
`window-icons.mjs`): та же обвязка, что у `session-mark.mjs` — `context`,
`ownTarget`, менеджер по машине окна, `--url`/`--machine`, `--json`, коды
выхода `0/1/2/3`. Сессия без окна — код 2, если не названа машина
(`--machine`/`--url`): тогда заданное сохраняется там и встанет с окном. Окон на двух машинах — ставится на всех,
как отметки `unread/seen`. Повтор безопасен (идемпотентно), код 3 можно
повторять.

`claude-wt window icons` спрашивает машину окна своей сессии
(`CLAUDE_CODE_SESSION_ID`, как у остальных команд); `--machine`/`--url` —
другую. Окон на нескольких машинах — первая из них; списки разных машин не
сливаются (*решение исполнителя дизайна*).

**Скиллы** `~/.claude/skills/set-icon`, `~/.claude/skills/set-badge`: когда
звать (агент хочет выделить свою сессию или ребёнка; «поставь иконку
telegram»), как узнать имена (`claude-wt window icons`), как снять, что
явное перебивает правила и значок head. Строка о командах — в скилле
`claude-wt-cli`.

## Что оставлено исполнителю

- Точные имена файлов модулей и функций, форма отпечатка.
- Место JSON-файла в каталоге данных и его имя.
- Текст отказов (английский, по образцу соседних команд).
- Как CLI печатает список имён без `--json`.

## Выкатка и проверка

Ветки `feat/session-icon` в windows11-manager и ccfzf, PR в каждом, мерж по
слову Стаса. Выкатка менеджера — только nb (`deploy-pc.sh --no-build`), живой
конфиг: `windowIcons.dir: 'C:\images\ico'` с бэкапом и `cmp`. CLI —
симлинк `~/bin/claude-wt` на основной клон ccfzf на pc-virt: новые команды
видны агентам, как только клон стоит на ветке с ними (до мержа — только по
слову Стаса, после — `main`).
Живая проверка: `claude-wt window badge <своя сессия> telegram` → строка
`значок C:\images\ico\telegram.ico` в журнале трея на nb; `--clear` → значок
вернулся к автоматике.
