# Слоты claude-wt на StreamDock

Пять кнопок физической доски показывают сессии Claude Code картинкой 128×128 и
поднимают окно сессии нажатием. Дорога — http, тот же слушатель на 9722, что уже
принимает просьбы пикера.

Задача приехала из `ccfzf-picker/docs/TODO.md`; там она снята, потому что делается
здесь. Причина переезда: в этом проекте уже готовы все три части — слушатель
(`src/http-server.js`), строитель слотов (`src/claude-wt/ha/session-slots.js`) и
подъём окна (`focus` в `src/commands/claude-commands.js`). В пикере пришлось бы
писать http-сервер и рендер текста на Rust с нуля.

Работы в двух репозиториях: здесь — сервер и картинка, в
`/home/popstas/projects/js/streamdock-http-button` — три правки плагина и скрипт
выкатки.

## Что уже есть, и на чём это стоит

- `startHttpServer({ router, port, log })` поднимается из `startService()`
  (`src/mqtt/service.js`) **всегда**, брокер для него не нужен. Порт — `httpPort`
  верхнего уровня конфига, умолчание 9722.
- `buildSlots(sessions, count, sort)` и `slotStatus(session)` в
  `src/claude-wt/ha/session-slots.js` — чистые, без I/O. Статусы: `active`,
  `question`, `review`, `idle`, `closed`, `empty`.
- `winMan.claudeWtSessions()` читает общий дамп (кэш 15 с, обход вранья SMB —
  `readDump()` в `sessions.js`), `labelSessions` доклеивает подписи.
- `throttlePress` (`src/commands/press-throttle.js`) — не чаще раза в секунду на
  ключ; отброшенное доезжает до http как `DROPPED` и отвечает 429.
- Плагин `pro.popstas.httpbutton`, действие `imageButton`: тянет картинку по
  `imageUrl` каждые `updateInterval` (умолчание 60 с), ужимает до 128×128 и
  ставит на кнопку. Нажатие сейчас только перечитывает картинку.

## Слоты

Свой снимок, тем же строителем. Новый модуль `src/claude-wt/dock/slots.js`:

```js
createDock({ winMan, config, log })
  .slots()        // снимок, не старше interval
  .svg(n)         // строка SVG, либо null — номер вне диапазона
  .resolve(n)     // { id } | { empty: true } | null — номер вне диапазона
```

Окна модуль не поднимает: `resolve` только называет сессию, `focus` зовёт
команда (ниже). Ввода-вывода у модуля тогда не остаётся, кроме чтения дампа, и
обе дороги проверяются без подмены оконного менеджера.

Снимок один на обе дороги и обновляется не чаще `interval` (умолчание 10 с).
Это главное свойство модуля: картинка и нажатие обязаны приходить из одного и
того же снимка, иначе кнопка поднимет не ту сессию, которая на ней нарисована.
Ровно так же устроен `claude-focus-slot` для панели openHASP — он резолвит номер
по `lastSlots` последнего экспорта, а не по свежему чтению.

Снимок строится так же, как для Home Assistant, и это осознанное повторение, а не
дублирование: строитель, сортировка и фильтр — те же функции и те же умолчания,
разойтись им негде.

```js
const sessions = labelSessions(winMan.claudeWtSessions().sessions);
const slotSessions = cfg.openOnly ? sessions.filter((s) => s.open) : sessions;
buildSlots(slotSessions, cfg.slots, cfg.sort);
```

**Почему не `haExport.slots()` напрямую.** Тот наполняется тиком экспорта, а тик
заводится только при подключении к брокеру. Доска от брокера не зависит вовсе:
`focus` — локальный вызов, слушатель поднимается без mqtt. Взяв чужой снимок, мы
погасили бы кнопки на время, когда всё нужное для их работы живо.

## Роуты

| Путь | Метод | Ответ |
|---|---|---|
| `/claude-wt/slot/<n>.svg` | GET | 200 `image/svg+xml; charset=utf-8`, `Cache-Control: no-store` |
| `/claude-wt/slot/<n>/press` | POST | 200 `{"ok":true}` / 200 `{"ok":true,"empty":true}` / 429 |

Номер вне диапазона `1..cfg.slots` — 404 у обеих дорог: это опечатка в настройке
кнопки, и молчать о ней нельзя. Нажатие на **пустой** слот — не ошибка, а пустая
кнопка: 200 с `empty: true` и строка в логе.

В `src/http-server.js` появляется ветка GET **до** нынешней проверки метода
(сейчас всё, кроме POST, получает 405). Роутер команд ветка не трогает и по GET
не открывается — на это отдельный тест: командные пути обязаны и дальше отвечать
405 на GET.

`startHttpServer` принимает необязательный `dock`. Его нет (блока `streamdock` в
конфиге нет или `enabled: false`) — оба пути отвечают 404, как всякий незнакомый
путь.

Нажатие идёт через роутер команд, а не мимо него: новая команда
`claude-dock-press` в `src/commands/build.js`, обёрнутая тем же `throttlePress`,
что и `claude-focus-slot`, — палец, снятый неровно, даёт две-три посылки подряд.
Тело `{ slot: n }`, номер сервер берёт из пути. Команда зовёт `dock.resolve(n)`
и, если сессия названа, тот же `focus({ id })`, каким живут `claude-focus` и
`claude-focus-slot`; пустой слот — строка в лог и `{ empty: true }` наружу.

## Картинка

`src/claude-wt/dock/render.js`, чистая функция без I/O:

```js
slotSvg(slot, { size = 128 }) -> string
```

Фон заливается цветом состояния целиком, текст белый.

| Статус | Фон | Знак |
|---|---|---|
| `active` | `#2e7d32` | `>` |
| `question` | `#b26a00` | `?` |
| `review` | `#c62828` | `!` |
| `idle` | `#3a3a3e` | `–` |
| `closed` | `#26262a` | `x` |
| `empty` | `#141416` | номер слота бледным |

Раскладка сверху вниз: имя проекта (11px, `fill-opacity: .75`, одна строка,
хвост — многоточием), имя сессии (15px, до двух строк, перенос по словам), внизу
слева процент контекста, внизу справа знак состояния. Пустой слот — тёмный
прямоугольник с номером по центру: видно, что кнопка настроена, а сессии в ней
нет.

Правила, из которых нельзя выходить:

- **Только `<text>`, никакого `foreignObject`.** Рисует SVG сам StreamDock, и
  ждать от него полноценного html-движка нельзя.
- **Ширина текста считается приблизительно, по числу знаков.** Измерить текст на
  сервере нечем; та же приблизительность уже работает в `makeKeySvg` плагина.
  Кегль 15 на 112 px полезной ширины — около 13 знаков в строке.
- **Экранируются `& < > " '`.** Имя сессии приходит от человека и от агента;
  один `&` в заголовке ломает весь документ, и кнопка гаснет молча.
- **Шрифт — `"Segoe UI", Roboto, sans-serif`.** Кириллица в именах сессий обычна,
  и первый в списке её точно несёт на целевой машине.

## Конфиг

Блок верхнего уровня, рядом с `homeassistant` — **не внутри `claudeWt`**: там он
молча ничего не сделает, ровно как `placeWindowOnOpen`, `publishStats` и сам
`homeassistant`.

```yaml
streamdock:
  enabled: true
  slots: 5
  interval: 10      # секунд: срок годности снимка слотов
  sort: recent      # тот же список, что у homeassistant.sessionsSort;
                    # под именем sessionsSort ключ читается тоже — иначе
                    # строка, скопированная из блока homeassistant, молча
                    # дала бы умолчание вместо заданного порядка
  openOnly: true
```

Живой конфиг — `C:\Users\popstas\AppData\Roaming\windows-mqtt\windows11-manager.config.yaml`
(первый путь у `resolveConfigPath()`; соседние `.js`, `.bak`, `.pre-yaml` —
наследство миграции и не читаются). `config.example.yaml` сам собой не читается
никогда: новый ключ переносится в живой конфиг руками, и это отдельный шаг в
задаче деплоя.

## Плагин

Три правки в `imageButton`, ничего сверх.

1. **Настройка `actionUrl`** и поле на странице `src/pages/actions/imageButton.vue`,
   i18n en/zh — как у соседних полей.
2. **Действие по нажатию.** `keyUp`/`touchTap`: сначала `POST actionUrl`, затем уже
   существующее принудительное перечитывание картинки. Порядок именно такой —
   окно поднимается сразу, а обновление следом покажет уже снятое «требует
   внимания». Пустой `actionUrl` — прежнее поведение, только перечитывание.
3. **Ветка SVG.** Ответ с `Content-Type: image/svg+xml` уходит в `setImage`
   как есть, мимо `resizeAndCropImage`. Канвас полагается на intrinsic-размеры
   картинки, у SVG они бывают пустыми, а наш и без того ровно 128×128. Дорога
   проверена: `httpButton` кормит `setImage` SVG-data-URI уже сейчас.

Тестов в плагине нет (vitest не подключён), заводить ради двух правок не будем —
проверка живая.

## Выкатка

**Менеджер.** Правка целиком в node-части, трей пересобирать незачем:

```
./data/scripts/deploy-pc.sh --no-build
```

Точечно, без выкатки, — тумблер «Stop service» → «Start service» в трее.

**Плагин.** Новый `data/scripts/deploy-win.sh` в репозитории плагина (`data/`
там уже в `.gitignore`), по образцу `ccfzf-picker/data/scripts/deploy-win.sh`:

```
ssh popstas-pc → D:\projects\js\streamdock-http-button
git fetch/checkout/pull → npm ci → npm run build → перезапуск StreamDock
```

Проверено живьём 2026-08-26: репозиторий на машине есть, node v24.12.0 и npm
11.4.2 стоят, `StreamDock.exe` — `C:\Program Files (x86)\StreamDock\StreamDock.exe`,
работает в интерактивной сессии (Console 1).

Два свойства этой машины, из которых растёт весь скрипт, — те же, что у выкатки
пикера. Копировать `dist` руками **не надо и нельзя**: `script/autofile.cjs`
последним шагом сам сносит
`%APPDATA%\HotSpot\StreamDock\plugins\pro.popstas.httpbutton.sdPlugin` и кладёт
туда свежую сборку; продублируй путь в скрипте — и он разойдётся с плагином при
первом же переименовании. Запуск StreamDock — `schtasks /ru popstas /it`: прямо
из ssh процесс сел бы в session 0, где нет ни рабочего стола, ни доски. Флаги
`--no-build` и `--no-launch` — как у соседей.

   происходит и в логе строка.

## Известные ограничения — названы сознательно

- **Менеджер поднимает только свои окна.** Сессия, живущая на маке, в слот
  попадёт (дамп общий), а нажатие на неё не сделает ничего. Ровно то же сейчас у
  панели openHASP. Пикер это умеет (`transport_for` выбирает транспорт по машине),
  менеджер — нет, и заводить в нём вторую такую развилку ради пяти кнопок не
  стоит.
- **Картинка отстаёт** на `updateInterval` плагина плюс до `interval` снимка.
  При 10 с и 10 с худший случай — 20 с. Нажатие при этом промахнуться не может:
  оно резолвится по тому же снимку, что и картинка.
- **Снимок и нажатие живут своим сроком годности**, не подписаны на события.
  `haExport.refresh()` после фокуса доски не касается: пересчёт всё равно
  случится в пределах `interval`.

## Чего не делаем

- Залипающих слотов (сессия держит номер, пока жива). Порядок выбран «точно как
  в HA-экспорте»; залипание — отдельное поведение, и заводить его надо сразу в
  обоих местах, иначе панель и доска разойдутся.
- Своего порта и своего слушателя. Слушатель есть, порт есть.
- PNG. Рендер растра на сервере — это шрифт в зависимостях; SVG проверен и
  бесплатен.
- Тестов в плагине.
