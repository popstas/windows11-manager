# Бейджи окон по заголовку внутри проекта

Дата: 2026-11-23. Решения Стаса в этом разговоре; помеченное «решение агента» —
выбор исполнителя, который Стас видел и не поправил.

## Зачем

Однотипных сессий стало много, и различать их нужно по типу сессии, а не только
по проекту. В ExpertizeMe живут десятки сессий `…-tg-…` (45 в дампе на
2026-11-23) и `planfix_bot-tg-…` (7), в home — `srb-…` (3); с одной иконкой
проекта на кнопке панели задач они неразличимы.

## Цели

- Окно сессии получает значок на кнопке панели задач
  (`ITaskbarList3::SetOverlayIcon`) по правилу «заголовок совпал с регэкспом».
- Правила живут в записи проекта `claudeWt.projects[].badges` и действуют только
  на сессии этого проекта.
- Внутри проекта правила упорядочены, срабатывает первое совпавшее.

## Не цели

- Пикер, заголовок окна, Alt+Tab: значок только на кнопке панели задач (вариант A
  — решение Стаса). Захочется в пикере — отдельная задача поверх (менеджер
  публикует значок, ccfzf пропускает поле, пикер рисует).
- Иконка проекта (`WM_SETICON`) не меняется.
- Поле в окне настроек трея: `badges` правятся руками в конфиге (решение агента).
- Глобальный, не привязанный к проекту список правил — отвергнут Стасом.

## Анти-цели

- Значок head не должен пропасть у head-окна из-за совпавшего правила.
- Кривой регэксп в конфиге не должен ронять тик службы иконок и гасить остальные
  правила.

## Подходы

1. **Правила в записи проекта** — `claudeWt.projects[].badges: [{match, icon}]`.
   Выбран: тип сессии у Стаса привязан к проекту (`tg`/planfix — ExpertizeMe,
   `srb` — home), новый тип — строка в живом конфиге, менеджер перечитывает его
   по mtime.
2. **Глобальный список `windowIcons.titleBadges`** — был предложен первым,
   Стас поправил: правила должны быть на уровне проекта.
3. **Зашить правила в код** — каждый новый тип стоил бы PR и выкатки, а их и
   стало много. Отвергнут.

## Как

- Конфиг:

  ```yaml
  claudeWt:
    projects:
      - name: expertizeme
        cwd: /home/popstas/projects/text/obsidian/ExpertizeMe
        badges:
          - { match: '^planfix_bot-tg-', icon: 'C:\images\ico\planfix.ico' }
          - { match: '-tg-',             icon: 'C:\images\ico\telegram.ico' }
      - name: home
        cwd: /home/popstas/projects/text/obsidian/home
        badges:
          - { match: '^srb-', icon: 'C:\images\ico\serbia.ico' }
  ```

- Проект выбирается по **точному** cwd сессии — так же, как иконка проекта в
  `projectIconFor` (решение агента: одна и та же сессия не должна получать
  иконку от одного проекта, а значок от другого). По дампу на 2026-11-23 все
  совпадающие сессии запущены ровно в корне своего проекта.
- `match` — регэксп JS по заголовку окна, очищенному `stripTitleDecoration`
  (то есть по имени сессии, без приставок zellij/WezTerm).
- Решает `iconFor` в `src/claude-wt/window-icons-helpers.js`: сейчас он
  отдаёт `{icon, overlay}` и значок ставит только head. Заголовок до него сейчас
  не доезжает — `claudeWtWindowSessions` в `src/claude-wt/view.js` отдаёт
  `{id, sessionId, cwd, focusedAt}`, заголовок окна есть только у вызывающего
  (`terminalWindows()` в `src/mqtt/window-icons.js`).
- Порядок значка: head в режиме `badge` → значок head; иначе первое совпавшее
  правило проекта; иначе без значка. В режиме `headMode: icon` слот значка
  свободен и правило работает (решение агента).
- Кривой регэксп пропускается, warn в журнал один раз на регэксп (решение
  агента), остальные правила работают.
- Относительный `icon` разрешается от корня репозитория, как у остальных
  иконок (`resolveIconPath`).
- `badges` не уезжают в файл трекера (`project-helpers.js`, запись проекта для
  ccfzf): читателю они не нужны (решение агента).
- Правки текста конфига (`patchProjectType`, `patchProjectIcons`) обязаны
  оставить `badges` нетронутыми — у `patchProjectType` есть сверка разобранного
  до и после, проверить, что она не спотыкается о список внутри записи.

## Ресурсы

- `telegram.ico` — извлечён из `Telegram.exe` (Telegram Desktop) с исходными
  кадрами 16/24/32/48/256.
- `serbia.ico` — флаг 🇷🇸 из Twemoji 14.0.2 (CC-BY 4.0), кадры 16–256.
- `planfix.ico` — уже лежит на nb, единственный кадр 256; на 16 px Windows
  уменьшает его прилично, файл не трогаем.
- Новые файлы — в `C:\images\ico` на nb, существующие не перезаписываются.

## Выкатка и проверка

- Иконки — `scp` в `C:\images\ico` на nb.
- Живой конфиг `%APPDATA%\windows-mqtt\windows11-manager.config.yaml`: бэкап
  `.bak-2026-11-23-badges`, правка локально, `scp` обратно, сверка `cmp`.
- Код — `./data/scripts/deploy-pc.sh --no-build` (меняется только node).
- Доехало: в журнале трея строка про значок `…telegram.ico` у окна `…-tg-…`, и
  ни одной строки про значок у окон других проектов.
