# Окна входящих из Telegram — в фоне

## Зачем

Окно сессии на входящий файл из Telegram открывается внезапно и забирает фокус:
`openInboxSession` → `focusSpawnedWindow` явно поднимает окно и при нужде
переключает рабочий стол (`focusTerminalWindow` → `GoToDesktopNumber`). Человек
в этот момент работает в другом окне, и его выдёргивает.

## Цели и не-цели

- Цель: режим «открыть в фоне» — окно запускается и ставится на место как
  сейчас, но фокус и рабочий стол не трогаются. Включён для `telegramInbox`.
- Цель: `gapMs` по умолчанию 3000 → 1000 мс (в фоне окна за фокус не дерутся).
- Не-цель: возвращать фокус окну, активному до запуска (решение Стаса:
  за время открытия фокус мог смениться — доделаем, если понадобится).
- Не-цель: никакой дополнительной постановки (отправить окно назад,
  свернуть, мигание кнопки) — позиции и так меняются по своим правилам.
- Анти-цель: сломать фокус у проектных хоткеев, `session-new`, restore.

## Подходы

Где оказывается фоновое окно:

- **A. Там, где его поставит обычная постановка, без фокуса** — выбран.
- B. Свёрнутым с миганием кнопки — не встанет в зону, пока не развернёшь.
- C. На отдельном рабочем столе «входящие» — не видно, пока не заглянешь.

Отдельно отвергнуто: запоминать активное окно и возвращать ему фокус (см. не-цели).

Известное ограничение A: `wt.exe` иногда сам выходит на передний план
(гонка, описанная в `project.js` у `focusSpawnedWindow`). Это не лечится —
мы лишь перестаём поднимать окно сами.

## Дизайн

- `focusSpawnedWindow(title, deps)` получает `focus` (по умолчанию `true`).
  При `false` — ждёт окно, `settleMs`, `place(...)` как сейчас, затем
  `mark('focus:skipped')` и `return true` (та же ветка, что у ребёнка head с
  `placed.focus === false`).
- `openInboxSession({..., background})` передаёт `focus: !background` в
  `focusSpawnedWindow`. Поле результата `focused` остаётся «окно нашлось»
  (в фоне — без фокуса); предупреждение «window did not show up in time» в
  наблюдателе работает как раньше.
- Конфиг: `claudeWt.telegramInbox.background`, по умолчанию `true` (моё
  решение: режим просили именно для этого сценария, на nb конфиг не трогаем).
  `false` возвращает старое поведение. Нормализация — в
  `telegram-inbox-helpers.js` рядом с `gapMs`.
- `gapMs` по умолчанию 1000 в `telegram-inbox-helpers.js`; `config.example.yaml`,
  README и AGENTS.md (абзац про очередь и фокус) обновить.
- Живой конфиг nb: в `claudeWt.telegramInbox` явно `gapMs: 1000` (решение
  Стаса). Правка scp'ом целиком, UTF-8 без BOM, бэкап `.bak-2026-11-13` рядом.
- GUI, вкладка Claude: группа «Telegram inbox» с полями
  `claudeWt.telegramInbox.gapMs` (число, плейсхолдер 1000) и
  `claudeWt.telegramInbox.background` (галка, умолчание true — моё решение:
  тот же механизм, одно поле). Rust (`get/save_claude_config`) и `settings.js`
  от имён полей не зависят — не меняются.
- Поля вкладки сейчас только второго уровня (`section.key`). Расширение:
  `section` может быть путём через точку (`claudeWt.telegramInbox`);
  `readClaudeConfig`, `patchConfigScalar`/`findTarget`/`verifyPatch` идут по
  пути (`doc.getIn`). Промежуточной карты нет (нет блока `telegramInbox`) —
  читаемый отказ «допишите блок вручную», а не вставка вложенной секции:
  без `dir`/`cwd`/`script` блок всё равно не работает. Тест умолчаний полей
  `claudeWt.telegramInbox.*` сверяет с `normalizeInboxConfig({})`.
- Тесты: `focusSpawnedWindow` с `focus: false` не зовёт `focus`, но зовёт
  `place`; `openInboxSession` пробрасывает `background`; нормализация конфига
  (`background` по умолчанию `true`, `gapMs` 1000).
- Выкатка: тесты здесь, затем deploy на nb
  (`TARGET_HOST=nb.popstas.pro REPO='C:\projects\js\windows11-manager' ./data/scripts/deploy-pc.sh`).
