# claude-place — раскладки tile/cascade для терминалов Claude

Статус: дизайн утверждён, к реализации не приступали
Дата: 2026-08-18

## Проблема

Кнопки «разложить плиткой» и «разложить каскадом» есть в ccfzf-picker и на панели
openHASP, и кнопки эти одни на все хосты. `macos-windows-manager` v0.4.0 обе
просьбы слушает и выполняет; здесь их не слушает никто, поэтому на
Windows-строках пикера кнопка молчит — молча, потому что у публикации в MQTT
ответа нет.

Нужны те же две раскладки, той же просьбой, с тем же разбором тела. Разойтись с
маком в разборе одного топика — это отладка сразу на двух машинах.

## Скоуп

Входит:

- просьба `claude-place` по MQTT, тело `{"mode": "tile"|"cascade", "ids": [...]}`;
- плитка **по зонам FancyZones**, список зон — в конфиге;
- запасная своя сетка (порт маковской арифметики), когда зон нет;
- каскад — порт маковского дословно;
- команда CLI `claude-wt place tile|cascade` для отладки без брокера.

Не входит:

- **пункты в трее Tauri.** Это Rust и отдельная сборка на Windows, а просьба по
  MQTT покрывает и пикер, и панель — ради них задача и заведена. Отдельной
  строкой в `# future`.
- **перенос окон между виртуальными столами.** Раскладка — про геометрию;
  окно, живущее на другом столе, получает новые границы там же, где стояло.
  Обещать больше значит спорить с claude-wt, который эти столы и помнит.
- **запоминание раскладки.** Слот доучивается нынешним положением окна сам, как
  и на маке; отката к прежней раскладке нет.

## Главное отличие от мака

На маке сетка считается арифметикой: экран делится на колонки шириной 80–120
знаков. Здесь зоны уже нарисованы человеком в FancyZones, и делить монитор
второй раз — значит спорить с тем, как он его поделил.

Поэтому плитка раскладывается **по списку зон из конфига**, а маковская
арифметика остаётся запасным путём — для машины, где FancyZones не настроен.

## Единицы и координаты

Всё считается в тех же координатах, в которых работают `getBounds()` и
`setBounds()`, — виртуализированных логических пикселях (AGENTS.md: «4K при 125%
выглядит как 3072×1728»).

**DPI в расчёт не входит.** Порог «80–120 колонок» задан в знаках, но терминал
DPI-aware и рисует шрифт крупнее ровно во столько же раз, во сколько
виртуализация ужимает координаты, — в этом пространстве ширина знака постоянна.
Значит `COL_PX` — одна константа, как `COL_PT` на маке, и никакого
`getScaleFactor()` рядом с ней быть не должно.

Поправку масштаба при переезде окна между экранами с разным DPI делает
`placeWindow()` (`adjustBoundsForScale`), и делать её второй раз здесь нельзя.

## Рабочая область

Отдаёт `monitor.getWorkArea()` — `MONITORINFO.rcWork` из vendored
node-window-manager (`vendor/node-window-manager/lib/windows.cc:369-385`), то
есть экран без панели задач, в том же пространстве, что `getBounds()`. Метод
есть у каждого `Monitor`, добывать его отдельно не нужно.

Монитор — тот, на котором стоит **первая зона из `tileZones`**; ключа нет или
зона не разрешилась — главный. Так каскад и плитка ложатся на один экран: тот,
который человек отвёл под терминалы.

Монитор первой зоны ищется **по её разрешённому прямоугольнику**, а не по номеру
из конфига:

```js
const mon = (rects[0] && getMonitorByPoint(rects[0])) || getPrimaryMonitor();
const work = mon.getWorkArea();
```

Номер в `tileZones` — номер монитора FancyZones (`getSortedMonitors()` по
`editor-parameters.json`), а `getMons()` нумерует по `config.monitors`; это две
разные нумерации, и сводить их здесь — заводить третье место, где они могут
разойтись. Прямоугольник от `fancyZonesToPos()` уже в логических координатах, и
`getMonitorByPoint()` (он же `findMonitorByPoint`) отвечает на вопрос без всякой
нумерации.

`src/monitors.js` получает только `getPrimaryMonitor()` — `getWindowsMonitors()`
плюс `find(m => m.isPrimary())`.

## Модули

| `src/claude-layout.js` (новый, I/O) | зоны через `fancyZonesToPos`, рабочая область, список сессий; двигает через `placeWindow` |
| `src/monitors.js` | `+getPrimaryMonitor()` |
| `src/commands/claude-commands.js` | `+claude-place` рядом с `claude-focus` |

| `src/index.js` | `+claude-wt place tile\|cascade` |

Разделение на чистое и I/O — тот же приём, что у `placement-helpers.js` и

Границы модулей и имена функций повторяют маковские `layout.rs` и `request.rs`,
чтобы правки ездили между проектами глазами.

## Разбор просьбы

Порт `parse_arrange` из `crates/mwm-core/src/request.rs` один в один. Три вида
тела, и все три обязательны:

- объект — `{"mode": "tile", "ids": ["a", "b"]}`; так шлёт пикер;
- строка JSON — `"tile"`;
- сырая строка — `tile`; так шлёт панель openHASP.

`ids` необязателен: пустой или отсутствующий список значит «все ведомые окна,
порядком этой машины». Имена раскладок — только `tile` и `cascade`, регистр не
важен, пробелы обрезаются. Незнакомое имя и пустое тело — `null`, строка `warn`
в журнал; уведомления нет, потому что это чужая просьба, а не поломка машины.

```js
parseArrangePayload(payload) // → { mode: 'tile'|'cascade', ids: string[] } | null
```

## Какие окна и в каком порядке

`ids` пуст → `claudeWtSessions()`, оставить `session.open && session.windowId`,
упорядочить `orderSessions(sessions, sort)` из
`src/claude-wt/ha/session-slots.js`, где
`sort = normalizeSort(getConfig().homeassistant?.sessionsSort)` из
`src/claude-wt/ha/session-groups.js` — тем же порядком и той же настройкой,
какими эта машина рисует панель. «Порядок этой машины»
на маке — порядок пунктов меню; здесь ему соответствует порядок панели, и
человек видит раскладку той же чередой, что список.

`ids` задан → порядок просящего. Каждый id ищется среди открытых сессий;
ненайденный пропускается со строкой в журнал (сессия закрыта или живёт на другой
машине) — просьба выполняется тем, что нашлось, а не отменяется целиком.

Окна берутся по `session.windowId` через `getWindowById()`; исчезнувший hwnd
(вернулся `null`) выбывает так же, как ненайденный id.

## Плитка по зонам

Конфиг:

```yaml
claudeWt:
  # Зоны FancyZones под терминалы claude, по порядку. Порядок списка —
  # порядок окон: первое окно списка встаёт в первую зону.
  tileZones:
    - { monitor: 1, position: 6 }
    - { monitor: 1, position: 7 }
    - { monitor: 1, position: 8 }
    - { monitor: 1, position: 9 }
```

Форма пары — та же, что у `rule.fancyZones` в правилах размещения
(`{monitor, position}`, позиции с единицы), и разрешается тем же
`fancyZonesToPos()`: он уже чинит DPI, `monitorsGaps` и `monitorsOffset`, и
второй такой же расчёт здесь заводить нельзя.

`tileByZones(rects, n)` — раскладка `n` окон по готовым прямоугольникам зон:

- `n === 0` или зон нет → пусто;
- окон не больше зон → по одному в первые зоны, остальные остаются пустыми;
- окон больше зон → зоны делятся по высоте поровну, добор идёт **с конца**.

Обе ветки считаются одной формулой, маковской (`layout.rs`, `tile()`), где
колонка заменена зоной:

```
base = floor(n / z)
rem  = n % z
окон в зоне k = base === 0 ? (k < rem ? 1 : 0)
                           : base + (k >= z - rem ? 1 : 0)
```

Внутри зоны окна делят её высоту поровну, нижнему достаётся остаток от деления —
иначе между ним и краем зоны остаётся щель в пару точек. Добор с конца потому,
что первое окно списка — самое верхнее в пикере, и зона ему достаётся целиком; с
добором слева полную зону получало бы последнее, до которого человеку дела
меньше всего.

Пример: зоны `[6,7,8,9]`, окон 6 → зоны 6 и 7 получают по одному окну, зоны 8 и
9 делятся пополам.

## Запасная сетка

Своя сетка считается, когда зон нет: ключ `tileZones` не задан, пуст, или хоть
одна зона из списка не разрешилась (FancyZones не настроен, раскладка не
`custom`, монитор отключён, `editor-parameters.json` протух).

**Откат всегда пишет строку `warn` с причиной.** Протухшие данные FancyZones —
известная болезнь этого проекта (AGENTS.md, «Known issues»), и тихий откат
спрятал бы её: окна просто встали бы не туда, и человек искал бы причину в
зонах.

`tileGrid(work, n)` — порт `tile()` и `columns()` дословно:

- колонок задаёт экран, а не число окон, и порядок ограничений важен — он и
  решает спор, когда экран узок настолько, что оба разом не выполнить:

  ```
  most  = max(1, floor(work.width / minWidth))   // больше — терминал уже 80 знаков
  least = max(1, ceil(work.width / maxWidth))    // меньше — терминал шире 120
  cols  = max(1, min(most, max(3, least)))       // три — идеал, most режет сверху
  ```

  На узком экране побеждает `most`, то есть нижний порог: читать узкий терминал
  хуже, чем широкий;
- ширина колонки `min(work.width / cols, maxWidth)` — обрезка по 120 знакам сторож, а не расчёт;
- окна раскладываются по колонкам той же формулой, что зоны выше, и делят высоту колонки поровну;
- нижнему окну колонки достаётся остаток от деления.

Константы:

```
MIN_COLS  = 80    // колонок на терминал, не меньше
MAX_COLS  = 120   // и не больше
COL_PX    = 10    // ширина знака: Cascadia Mono 12pt ≈ 9.6 px при 96 DPI
CHROME_PX = 32    // рамка, отступы, полоса прокрутки
```

`COL_PX` и `CHROME_PX` заведомо приблизительны, и это осознанно — ровно как
`COL_PT` на маке: ошибка в полпикселя сдвигает границу на несколько колонок, но
раскладку не ломает. Меряются один раз на живой машине и правятся здесь.

Проверка чисел: ultrawide 3440 → 3 колонки по 1146 px (≈111 знаков); 1920 → 2
колонки по 960 (≈92); 4K логических 3840 → 4 колонки по 960 (≈92).

## Каскад

Порт `cascade()` дословно, от рабочей области (не от зон — их каскад не
касается):

```
w         = work.width / 2
perStack  = 1 + max(0, min((work.width - w) / STEP, (work.height / 2) / STEP))
steps     = min(n, perStack) - 1
h         = work.height - steps * STEP
окно i    → x = work.x + (i % perStack) * STEP
             y = work.y + (i % perStack) * STEP
             width = w, height = h
```

`STEP = 50`: высоты заголовка хватило бы, чтобы окно опознать, но не чтобы за
него ухватиться. Высота считается по числу окон **в стопке**, а не по всему
списку: двум окнам ступенька нужна одна, и отдавать им столько же места, сколько
десяти, значит впустую резать высоту. Переполненная стопка начинается заново от
левого верхнего угла.

## Как двигаются окна

Через `placeWindow({ w, rule: { pos }, isBulk: true })` из `src/placement.js` —
он экспортируется, и переиспользовать его надо, а не звать `setBounds()` голым:
он уже умеет пропуск свёрнутых окон, пропуск «уже стоит там», поправку масштаба
при переезде между экранами, повтор при промахе и строку журнала в привычном
формате `from → to`.

`isBulk: true` глушит `bringToTop()` внутри. Плитке он не нужен вовсе
(перекрытий нет); каскаду нужен, и окна поднимаются отдельным проходом **в
порядке списка**, так что последнее оказывается сверху — как принято у каскада.

Одно упавшее окно не обрывает остальные: `placeWindow` зовётся с `.catch()`, как
в `placeWindowsByConfig`.

## Отчёт

- журнал: `claude-place tile: разложено 6 из 6` (и `… из 7`, когда кто-то
  выбыл), плюс строка `warn` на каждую пропущенную сессию и на откат к своей
  сетке;
- `notify` — только на отказ (тело не разобрано, открытых сессий нет). Успех в
  телефон не уходит: панель нажимают часто, и уведомление на каждое нажатие
  делает нечитаемыми все остальные.

## Ограничитель

`claude-place` регистрируется в `build.js` под `throttlePress`, как
`claude-focus-slot`: источник — палец на панели openHASP, снятый неровно палец
даёт две-три посылки подряд, а каждая раскладка — десяток `setBounds()`.
