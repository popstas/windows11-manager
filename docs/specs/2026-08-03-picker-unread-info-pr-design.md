# Пикер: mark unread, session info, PR сессии

Дата: 2026-08-03
Статус: утверждён

## Проблема

Три дыры в списке сессий, все со стороны человека, а не агента.

1. **Статус нельзя вернуть.** «Просмотрено» ставится первым же фокусом окна
   (`slot.focusedAt >= agent.updated`, `seenSinceUpdate()` в `progress-helpers.js`).
   Заглянул в сессию на секунду — оранжевый кружок стал серым, и вернуть его
   нечем. Для задач, где взгляд в окно ничего не решает, сессия теряется.
2. **Полей у сессии больше, чем видно в строке.** В строке помещаются имя, путь,
   запрос, сводка, статус, деньги и возраст; `desktop`, `monitor`, `bounds`,
   `agentEvent`, `agentSessionId`, `agentStarted`, `focusedAt` не видны нигде.
3. **PR сессии живёт ровно один ответ агента.** Ссылку на PR агент называет в
   сводке («Готово. PR: https://github.com/…/pull/3 — ветка …»), следующий ответ
   строку затирает. Через час найти PR, сделанный сессией, уже негде.

## Решение

### 1. Mark unread

`markSessionUnread(id)` — новый экспорт `src/claude-wt/index.js`. Правит
`liveState.slots[id]` и пишет состояние на диск.

Живёт в `index.js`, потому что демон крутится в процессе windows-mqtt
(`winMan.startClaudeWt()`), а `liveState` — приватная память модуля: правка файла
снаружи была бы затёрта следующим тиком. Отдельная запись файла нужна потому, что
пикер читает состояние с диска (`readState()` в `view.js`), а демон пишет его
только при изменении `layoutFingerprint()` — слоты входят в отпечаток целиком, так
что изменение `focusedAt` запись вызовет, но ждать до следующего тика незачем.

**Значение — `updated - 1`, не ноль.** `seenSinceUpdate()` вернёт `false` (сессия
непрочитана), но слот не выпадет из порядка `project-helpers.js`, который выбирает
«последнюю» сессию проекта по `focusedAt`. Обнуление сломало бы Ctrl+F11/F12 на
проектах с несколькими сессиями. Если у сессии нет записи хука (`updated === 0`),
пометка не имеет смысла — возвращаем `false`, пункт меню не показываем.

**Ловушка: пикер возвращает статус обратно.** Пикер — окно поверх; на Esc фокус
уходит тому окну, что было впереди до него, а помечают обычно ровно ту сессию, из
которой пришли. Демон видит переход фокуса, `focusedSessionIds()` отдаёт сессию,
`focusedAt` встаёт в «сейчас» — и только что помеченная строка снова серая.

Лечение: `markSessionUnread()` кладёт id в набор «пропустить следующий фокус» с
TTL 15 с. `focusedSessionIds()` получает набор параметром и вычитает его из
результата, погашенные id из набора убирает. TTL нужен, чтобы запись не жила
вечно, если человек в окно так и не вернулся. Набор и его чистка — в
`daemon-helpers.js`, чистыми функциями, тестируются без окон.

Пометка распространяется на сессии-близнецы по тому же правилу, что и фокус:
`focusedSessionIds()` гасит все слоты с одинаковым первым заголовком, значит и
подавлять надо их все.

**UI.** Пункт `Mark unread` в Ctrl+K (у любой сессии со слотом и записью хука) и
Shift+клик по строке списка. Пикер не закрывается: список перерисовывается раз в
секунду, кружок перекрашивается на глазах, можно пометить несколько подряд. Новое
действие `windows/claude-session-unread` рядом с `claude-session-open`. Shift+клик
по строке, которую пометить нечем (нет записи хука), не делает ничего — обычным
кликом он при этом не становится, иначе промах по Shift открывал бы сессию.

### 2. Session info

Оверлей той же конструкции, что и меню Ctrl+K: тот же `#actions-backdrop`, та же
палитра, Esc закрывает, клик по фону закрывает. Открывается пунктом `Session info`
из Ctrl+K и клавишей Ctrl+I из списка.

Данные — из уже пришедшей строки списка, без единого нового запроса: `id`, `label`,
`cwd`, `desktop`, `monitor`, `bounds`, `open`, `windowId`, `agentState`,
`agentEvent`, `agentMessage`, `agentPrompt`, `agentDescription`, `agentCostUsd`,
`agentContextPct`, `agentStarted`, `agentBackground`, `agentSessionId`,
`lastActivity`, `focusedAt`, `agentSeen`, `branch`, `pr_url`. Таблица «поле —
значение»; отметки времени — абсолютные плюс возраст (`14:32 · 5m`), пустые поля
пропускаются.

Сборка строк — чистая функция `buildSessionInfoRows(session, nowSec)` в новом
`frontend-src/session-info.js` с тестами; `sessions.html` только рисует. Файл
пикера уже 576 строк, логика из него выносится по одному месту за раз.

Приоритета в списке полей нет: такого понятия нет ни в хуках, ни в слотах, ни в
дампе ccfzf. Ручной приоритет — отдельный слой редактируемого состояния и отдельная
задача.

### 3. PR сессии

**Хук на pc-virt** (`wt-progress.sh`, правка на `V:`; деплой windows-mqtt не
нужен). Он и так читает хвост транскрипта ради сводки. Там же:

1. Ищет `https://github\.com/[^/]+/[^/]+/pull/[0-9]+`.
2. Узнаёт ветку: `git -C "$cwd" rev-parse --abbrev-ref HEAD`.
3. Нашёл ссылку — пишет пару в `~/.claude/claude-wt/prs.json`, ключ
   `<cwd>#<branch>` → `{url, updated}`.
4. В `<id>.state.json` кладёт готовые `branch` и `pr_url` — разрешённые по карте,
   даже когда сама эта сессия ссылку не называла.

Привязка к ветке, а не к сессии, даёт главное: PR переживает рестарт сессии под
новым id, а вторая сессия на той же ветке видит ту же ссылку сразу.

Узор тот же, что у денег и контекста из статуслайна: разрешает Linux-сторона, где
файлы локальные, на Windows приезжает одно готовое поле.

**Имя поля — `pr_url`**, как записано в задаче, хотя остальные поля хука в
`state.json` camelCase (`costUsd`, `contextPct`, `lastSummary`, `summaryAt`). Имя
проходит через всю связку неизменным: `state.json` → `normalizeProgress()` →
`buildSessionList()` → строка пикера.

**Номер PR** берётся из хвоста URL той же регуляркой, что его нашла
(`/pull/([0-9]+)`), отдельного поля не заводим.

**В списке.** Текстовая метка `↗ #3` в строке, рядом с меткой hotkey и тем же
тусклым стилем (`.name .hotkey`). Именно текст, а не картинка: в webview стоит
Segoe UI, стрелка в нём есть, а файлов-ассетов у пикера нет вовсе. Когда `pr_url`
пуст — метка не занимает ничего.

**В Ctrl+K.** Пункт `Open PR #3` — номер прямо в подписи; появляется только у
сессий с `pr_url`. Меню собирается на сервере (`availableActions()` в
`src/picker/session-open-helpers.js`), туда добавляется `pr_url` сессии.

**Открытие** — `cmd /c start "" <url>`, тот же путь, что у `Open in Explorer`
(проверено: `spawn explorer.exe` на этой машине не работает). Перед запуском URL
проверяется на `^https://github\.com/[^/]+/[^/]+/pull/[0-9]+$`: строка пришла из
транскрипта агента и в аргумент `start` без проверки попадать не должна.

## Границы

- Ручной приоритет, pin, произвольные статусы сессии — вне скоупа.
- `gh pr view` по ssh не зовём: PR берётся только из того, что агент сам назвал.
- Панель openHASP не меняется — ни PR, ни «непрочитано» на неё не уезжают.
- Session info ничего не запрашивает дополнительно: показывает только то, что уже
  есть в строке списка.

## Проверка

- `npm test` в `windows11-manager` — `markSessionUnread`, подавление фокуса в
  `focusedSessionIds()`, разбор `branch`/`pr_url` в `normalizeProgress()`.
- `npm test` в `windows-mqtt` — `buildSessionInfoRows()`, состав действий с `pr_url`
  и без, валидация URL.
- Руками: пометить сессию непрочитанной из её же окна (Ctrl+Space → Ctrl+K → Mark
  unread → Esc) и убедиться, что кружок остался оранжевым после возврата фокуса.
- Руками: Ctrl+I на строке, `Open PR #N` в Ctrl+K у сессии, где агент называл PR.
- Деплой: правки node — `npm run deploy-fast`; правки `sessions.html` /
  `frontend-src/` — `npm run deploy-local` (см. скилл claude-wt).

## Порядок работ

1. Mark unread (целиком на Windows).
2. Session info (целиком на Windows).
3. PR: хук на `V:`, затем поля и UI.
