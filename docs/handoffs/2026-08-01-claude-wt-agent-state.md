# Handoff: состояние агента, снапшоты, панель openHASP

Сессия 2026-08-01. Работа шла в четырёх местах сразу: два репозитория, хуки на
pc-virt и конфиги умного дома на shome.

## Что сделано

### windows11-manager — ветка `feat/claude-wt-agent-progress` (8 коммитов, запушена)

- **`46c6253` возврат потерянного слоя view.** `view.js`, `view-helpers.js` и
  `focusWindow` были в опубликованной 2.0.0, но отсутствовали **в git целиком** —
  версию выложили из рабочего дерева с незакоммиченными файлами. Восстановлены из
  установленной копии.
- **`1cddde0`, `89cec86` состояние агента.** Хуки на стороне агента пишут
  `state`/`event`/`message`, `claudeWtSessions()` отдаёт их как `agentState`,
  `agentEvent`, `agentMessage`, `lastActivity`.
- **`d55e4ce` фокус как признак «просмотрено».** Демон запоминает `focusedAt` в
  слоте; `agentSeen` означает «окно выходило вперёд после записи агента». Читается
  голый `addon.getActiveWindow()` (0.0001 мс), отметка ставится только на переходе
  фокуса — иначе слот, а с ним и файл, переписывались бы каждую секунду.
- **`48f9103` мониторы.** `getMonitor()` собирал массив только из найденных, и один
  отключённый монитор сдвигал все следующие — правила размещения молча уезжали не
  на тот экран. Плюс сопоставление стало терпимым к повороту (ultrawide стоймя) и
  DPI (4K при 125% приходит как 3072×1728).
- **`975eadd` снапшоты раскладов.** `restore` не работал в принципе: `lastLayout`
  обнуляется через полторы секунды после закрытия окон, замерено. Снимок пишется,
  когда состав устоялся (дебаунс), изменение одних координат переписывает последний
  снимок. Команды `snapshots-list`, `snapshots-restore [id|last]`; `restore` стал
  алиасом `snapshots-restore last`, прежнее поведение под `--slots`.
- **`a1445b5` доверие хукам вместо флага `live`.** В дампе ccfzf `live` бывает
  неверен: замерено, что у двух сессий с заголовком `shared` работала та, где стоял
  `live=false`. Теперь побеждает сессия со свежим файлом хука. Бюджет цикла
  соблюдён: только mtime, только для спорных заголовков, 2 stat в тик вместо 1.

Тесты: 348.

### windows-mqtt — ветка `feat/session-picker-agent-state` (15 коммитов, запушена)

- Пикер: пять состояний кружка, возраст активности, тултип с полным cwd и
  сообщением агента, живые сессии отдельной группой сверху, текстовый статус.
- Раскладка по фиксированным слотам (живые по столам, закрытые по свежести).
- **Экспорт в Home Assistant через MQTT Discovery**, устройство `claude-wt`:
  `switch.claude_wt_session_1..9` плюс `sensor.claude_wt_sessions`. Состояние `on`
  означает «требует внимания», нажатие в HA переводит фокус на сессию.
- Фокус и восстановление снимка по MQTT.
- `filewatch`: опрос для сетевых путей — SMB не отдаёт события файловой системы,
  chokidar падал с `EISDIR`.

Тесты: 172.

### pc-virt (через V:)

- `~/.claude/hooks/wt-progress.sh` переписан: помимо прогресс-бара пишет
  `<id>.state.json` (active / question / review / idle), атомарно, по файлу на
  сессию, с чисткой старше 7 дней.
- `~/.claude/hooks/claude-wt-agent-state.sh` — новый, на `SessionStart` пишет
  `<id>.meta.json`.
- Оба зарегистрированы в `~/.claude/settings.json`.

### shome / Home Assistant (через R:)

- `openhasp_generate_config.py` научился арифметике: `openhasp_lines.src.yaml` с
  блоком `vars` и выражениями `'= ...'` раскрывается в обычный
  `openhasp_lines.yaml`. Считает не через `eval` — разбирается дерево выражения,
  пропускаются только числа, имена и арифметика.
- Страница 3 панели: девять строк во всю ширину + три кнопки команд (ccfzf,
  Restore last). Пейджер закольцован на три страницы. Кнопки `p0b41`/`p0b42`
  разведены на страницы 1 и 2 (были на странице 0, то есть на всех сразу).
- `openhasp_generate_service.sh` — наблюдатель на inotify с дебаунсом.

## Что осталось

### Требует действий на стороне пользователя

1. **Плата не получила новую геометрию.** На экране старая раскладка, пока Node-RED
   не зальёт `pages.jsonl`. Толчок: публикация в `hasp/openhasp5/update`. До этого
   судить о ширине строк бессмысленно.
2. **`openhasp_lines.src.yaml` не в фильтре наблюдателя** — правки источника не
   подхватываются. Добавить имя в `case` внутри `openhasp_generate_service.sh`.
3. **`p3b92` свободна** — третья командная кнопка ничем не занята.
4. **Наблюдатель запущен из шелла**, а не как systemd-юнит: умрёт вместе с
   ssh-сессией. Юнит описан в переписке, нужен `loginctl enable-linger`.

### Требует решения

5. **PR не открывались.** Обе ветки запушены, `do finalize` не запускался.
6. **`launchDelayMs` в конфиге пользователя = 5000** (было 2000). Меняли для теста,
   разницы тест не показал — вернуть или оставить.
7. **Нумерация мониторов изменена** в личном конфиге: `1` теперь MSI (4K),
   IVM7613 уехал на `5`. Правила размещения, ссылавшиеся на `1`, теперь целятся в
   другой экран. Бэкап — `config.before-monitors.js` в scratchpad сессии.
8. **`sessionsRefresh` из спеки не реализован** — обновление дампа ccfzf по F5 и по
   нерезолвящемуся заголовку. Частично обесценено фиксом `a1445b5`, но случай
   «сессии вообще нет в дампе» остаётся.
9. **Дубли слотов по заголовку** — пункт «вне рамок» в спеке. Фокус не страдает
   (окно ищется по хэндлу), а `snapshots-restore` по id может поднять не тот
   транскрипт.
10. **Availability при жёстком убийстве.** `offline` уходит только при штатной
    остановке; нужен LWT, а соединением владеет Rust-сторона.
11. **Латентный баг в windows-mqtt**: `config?.store?.default` с последующим
    безусловным `stored.apps` — падение при старте, если секции нет. Заведён чип.
